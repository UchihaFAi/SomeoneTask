# SWGOH → `roster_clean.json`

Скрипт выгружает ростер Star Wars: Galaxy of Heroes через локальный
[SWGoH Comlink](https://github.com/swgoh-utils/swgoh-comlink) и собирает
компактный JSON для загрузки в Claude Project (рекомендации по составам
для арены / GAC).

> **Запускать нужно на своей машине.** В облачном окружении, где скрипт
> писался, сетевой доступ ограничен GitHub и пакетными реестрами, поэтому
> ни Comlink, ни игровые API оттуда недоступны — см. «Почему не запущено здесь».

> **Состояние на 12.10.2026.** Схема ответа `/player` сверена с wiki и не
> менялась; тесты проходят. Последний релиз Comlink — v4.5.0 от 7 августа 2026.
> **Его Windows-бинарник не запускается** из-за дефекта сборки, поэтому под
> Windows используйте Docker или релиз v4.4.2 — подробности в [WINDOWS.md](WINDOWS.md).

## Быстрый старт

**Windows, в один клик:** скачать [ZIP ветки](https://github.com/UchihaFAi/SomeoneTask/archive/refs/heads/claude/md-file-actions-6eixrc.zip),
распаковать, запустить **`run.bat`** — он сам поставит зависимость, поднимет
Comlink (Docker или бинарник), выгрузит ростер и откроет папку с результатом.
Подробности и разбор по шагам — [WINDOWS.md](WINDOWS.md).

Вручную:

```bash
# 1. Comlink: бинарник со страницы релизов под свою ОС...
#    https://github.com/swgoh-utils/swgoh-comlink/releases
./swgoh-comlink --name my-roster-export --port 3000 &

#    ...или контейнер (так рекомендует README самого проекта)
docker run -d --name swgoh-comlink -p 3000:3000 \
  -e APP_NAME=my-roster-export ghcr.io/swgoh-utils/swgoh-comlink:latest

# 2. Зависимости
pip install -r requirements.txt

# 3. Выгрузка (ally code без дефисов)
python fetch_roster.py 123456789
```

Ally Code можно передать и переменной окружения — в коде он не хардкодится:

```bash
SWGOH_ALLY_CODE=123456789 python fetch_roster.py
```

## Файлы на выходе

| Файл | Содержимое |
|---|---|
| `roster_raw.json` | сырой ответ `/player`, сохраняется всегда — до любой обработки |
| `roster_clean.json` | персонажи (`combatType == 1`) |
| `ships_clean.json` | корабли (`combatType == 2`), если их удалось отделить |

Пример записи:

```json
{
  "id": "DARTHREVAN",
  "stars": 7,
  "level": 85,
  "gear_tier": 13,
  "relic_tier": 9,
  "zetas": ["skill_revan_leader", "skill_revan_unique"],
  "omicrons": [],
  "mods": {
    "count": 6,
    "by_level": { "15": 6 },
    "by_tier": { "5": 6 },
    "by_rarity": { "6": 6 }
  }
}
```

## Ключи запуска

| Ключ | Назначение |
|---|---|
| `--url` | адрес Comlink (по умолчанию `http://localhost:3000`) |
| `--out-dir` | каталог для файлов |
| `--no-gamedata` | не запрашивать `/data`: быстрее, но без зет/омикронов и без деления на корабли |
| `--include-skills` | добавить полный список способностей с внутриигровыми тирами |
| `--timeout` | таймаут запросов, сек |

## Как разбираются данные

Схема сверена с [wiki проекта](https://github.com/swgoh-utils/swgoh-comlink/wiki/Player-Data),
а не взята из головы:

* `definitionId` (`"DARTHREVAN:SEVEN_STAR"`) → `id` = часть до двоеточия.
* `currentRarity` → `stars`, `currentLevel` → `level`, `currentTier` → `gear_tier`.
* `relic.currentTier` — это enum со смещением: **реальный уровень = значение − 2**.
  Если реликвия не открыта, получается `0`; если поля `relic` нет вовсе — `null`.
* `skill[].tier` — к значению прибавляется **+2**, чтобы получить внутриигровой тир.
* Персонажи и корабли различаются по `combatType` из коллекции `units`
  эндпоинта `/data` (1 — персонаж, 2 — корабль). В ответе `/player` этого поля нет.

### Зеты и омикроны

`/player` отдаёт только номер тира способности — без игровых данных понять,
является ли тир зетой или омикроном, невозможно. Поэтому скрипт дополнительно
тянет `/data`, находит в определениях способностей булевы флаги zeta/omicron
и помечает открытые тиры.

Имена этих полей не задокументированы в wiki, поэтому скрипт **определяет их
во время выполнения** по фактической структуре данных (кандидаты:
`isZetaTier`/`isOmicronTier` и синонимы) и печатает, что именно нашёл. Если
флаги не найдены или `/data` недоступен, `zetas` и `omicrons` становятся `null`
— вместо того чтобы подставлять выдуманные значения.

**Что стоит сверить один раз:** скрипт исходит из того, что при `skill.tier == N`
открыты записи определения с индексами `0…N-1`. После первого запуска сравните
строку «Всего зет» с количеством зет в игре. Если есть систематическое
расхождение на единицу — напишите, поправлю смещение.

### Моды

Кодировка сетов внутри `definitionId` мода не задокументирована, поэтому
названия сетов (`speed`, `health`, …) **не** восстанавливаются — вместо
выдуманного маппинга скрипт отдаёт распределение по полям, которые реально
присутствуют в ответе: количество модов, уровни, тиры, редкость. Если нужны
именно сеты — это делается отдельно и требует проверки по игровым данным.

## Проверки

### Тесты

```bash
python -m unittest discover -s tests
```

57 тестов, сети и запущенного Comlink не требуют — мок Comlink поднимается
на localhost. Они фиксируют правила разбора: смещение реликвий `-2`, смещение
тиров способностей `+2`, значения `combatType`, определение zeta/omicron только
по открытым тирам, отсутствие выдуманных имён сетов у модов и сохранение
`roster_raw.json` до начала обработки.

Отдельно покрыт оркестратор `run_export.py`: нормализация Ally Code, выбор
между Docker и бинарником, повторное использование уже запущенного Comlink,
остановка сервиса даже при падении выгрузки и проверка, что `run.bat` остался
ASCII-only.

### Самопроверка при запуске

После сборки скрипт сам проверяет, что:

* число записей в чистых файлах совпадает с числом юнитов в сыром ответе;
* нет дублей `id` и нет записей без `id`.

Расхождения печатаются, код возврата становится `2`. Валидность JSON можно
перепроверить вручную:

```bash
python -m json.tool roster_clean.json > /dev/null && echo OK
```

## Приватность

`.gitignore` исключает `roster_raw.json`, `roster_clean.json` и
`ships_clean.json` — личные игровые данные в репозиторий не попадают.
Ally Code нигде не сохраняется и в логе маскируется до последних трёх цифр.

## Почему не запущено здесь

Скрипт написан и протестирован, но фактическая выгрузка в этом окружении
невозможна по двум независимым причинам:

1. **Ally Code не был указан** — в постановке задачи стоит плейсхолдер
   `ЗАМЕНИТЬ_НА_СВОЙ_ALLY_CODE`.
2. **Сетевая политика окружения** запрещает исходящие соединения ко всем
   хостам, кроме GitHub и пакетных реестров (проверено: `example.com`,
   `google.com`, `ea.com`, `swgoh.gg` — все отклонены шлюзом с 403 на CONNECT).
   Значит, ни скачать релизный бинарник Comlink, ни дать ему достучаться до
   серверов Capital Games отсюда нельзя.

Корректность разбора проверена на моке, воспроизводящем документированную
схему ответа, — см. раздел «Проверки». Запускать `tests` можно и здесь:
они полностью локальные.
